
# OpenCV 與 YOLO 在 AOI 視覺辨識中的角色分析

> 整理日期：2026-05-28
> 專案：Low-Cost PCB AOI System
> 核心硬體：Raspberry Pi 5 (4GB) + Hailo 8L (13 TOPS) + IMX296 Global Shutter 相機

---

## 提問一：視覺辨識用 OpenCV 還是 YOLO 比較好？

### 先釐清：這不是二選一的問題

OpenCV 和 YOLO 本質上是不同層級的工具，在 AOI 專案中互為補充，而非競爭關係。

### 缺陷類型分析：傳統 CV vs 深度學習適合度

| 缺陷類別 | 光源 | 傳統 CV (OpenCV) 可行性 | YOLO 適合度 | 判定 |
|:---|:---|:---|:---|:---|
| **金手指表面異物** (`fm_on_gold`) | 同軸光（黑點） | ⚠️ 勉強可用模板匹配+差分，但金手指反光變化大，偽陽性極高 | ✅ 非常高 | **YOLO 必要** |
| **金手指間距異物** (`fm_in_gap`) | 同軸光 | ❌ 間距極窄（<0.5mm），傳統輪廓分析難以區分異物與正常邊緣 | ✅ 非常高 | **YOLO 必要** |
| **棕化面刮傷** (`oxidized_surface_scratch`) | 環形光 | ❌ 刮傷與自然氧化紋理極難用閾值/邊緣區分，這正是 DL 強項 | ✅ 非常高 | **YOLO 必要** |
| **軟板成形毛邊** (`edge_burr`) | 環形光 | ⚠️ 可用邊緣檢測+輪廓偏離分析，但不同料號需逐一手調參數 | ✅ 高 | **YOLO 更優** |
| **軟板撕裂/缺角** (`edge_tear`) | 環形光 | ⚠️ 同上，邊緣完整性檢查可行但不夠泛化 | ✅ 高 | **YOLO 更優** |

> **結論**：五類缺陷中，沒有任何一類是傳統 OpenCV 能穩定處理的。缺陷檢測主引擎必須是 YOLO。

### OpenCV 的真正角色：視覺管線的基礎設施

| OpenCV 角色 | 具體用途 | 可否取代？ |
|:---|:---|:---|
| **相機擷取** | `cv2.VideoCapture` / GStreamer pipeline 取幀 | ❌ 無法取代 |
| **影像 I/O** | `cv2.imwrite()` 存 JPG、`cv2.imread()` 讀檔 | ❌ 無法取代 |
| **前處理** | 縮放至 640×640、色彩空間轉換、正規化 | ⚠️ 可用 numpy/PIL 替代但更麻煩 |
| **ROI 裁切** | 根據 motion 座標裁切檢測區域 | ❌ 無法取代 |
| **視覺對位** | 找 fiducial mark、計算偏移量、仿射變換 | ❌ 純 OpenCV 經典應用 |
| **框繪製** | 在原圖上繪製 YOLO 輸出的 bounding box | ⚠️ 可用 PIL 替代 |
| **輔助品質檢查** | 亮度/對比度檢查（影像是否過曝/過暗） | ✅ 純 OpenCV 強項 |

### 正確分工架構

```
                    ┌──────────────────────┐
                    │   OpenCV (基礎設施)    │
                    │  - 相機擷取            │
                    │  - 前處理/ROI/對位     │
                    │  - 影像 I/O            │
                    │  - 品質預檢 (亮度等)    │
                    └──────┬───────────────┘
                           │ 送出預處理張量
                           ▼
                    ┌──────────────────────┐
                    │  YOLO + Hailo 8L     │
                    │  (缺陷檢測主引擎)      │
                    │  - 5 類缺陷偵測       │
                    │  - 信心度 + 邊界框     │
                    └──────┬───────────────┘
                           │ 缺陷清單
                           ▼
                    ┌──────────────────────┐
                    │   OpenCV (後處理)     │
                    │  - 繪製 bbox          │
                    │  - 座標映射 (px→mm)   │
                    │  - 結果圖儲存          │
                    └──────────────────────┘
```

### 專案現狀判斷

- Training Host 用 YOLO11 訓練 → ONNX → Hailo `.hef` ✅
- Edge 用 HailoRT 載入 `.hef` 做推理 ✅
- Edge 用 OpenCV 做相機擷取與 I/O ✅
- `inference.py` 中 `predict()` 仍為 stub，需補齊 HailoRT 實際推理與後處理接線 ⚠️

> **一句話**：YOLO（透過 Hailo 8L 加速）做缺陷辨識，OpenCV 做影像管線的基礎設施。兩者各司其職，缺一不可。

## 提問二：使用 OpenCV 判斷 Z 軸對焦（機械對焦）可行嗎？

### 答案：完全可行，且是標準做法

核心原理是**基於對比度的自動對焦 (Contrast-Based Autofocus)**：清晰影像有更多高頻細節（邊緣），模糊影像則沒有。

### 核心演算法：Laplacian Variance

```python
import cv2

def focus_score(image):
    """值越大代表越清晰"""
    gray = cv2.cvtColor(image, cv2.COLOR_BGR2GRAY)
    return cv2.Laplacian(gray, cv2.CV_64F).var()
```

### 可行性評估

| 考量 | 分析 |
|:---|:---|
| **光學特性** | 鏡頭 F/8.0，景深 ~3.2mm，爬山法 5-8 步即可找到峰值 |
| **相機幀率** | IMX296 @ 60fps，擷取 ~16ms，Laplacian 計算 < 5ms，每步 ~25ms |
| **Pi 5 算力** | Laplacian + variance 是輕量運算，Pi 5 完全輕鬆應付 |
| **Z 軸精度** | NEMA 17 + GT2 皮帶 + 微步進可達 0.01mm，遠小於 3.2mm 景深 |

### 對焦應用場景

| 場景 | 說明 |
|:---|:---|
| **PCB 厚度變化** | 不同料號板厚不同（0.8/1.2/1.6mm），焦距會偏移 |
| **多層板高度差異** | 金手指區與軟板區可能不在同一平面 |
| **機構熱膨脹** | 長時間運作後機構微變形 |
| **換線校準** | 每次更換檢測程式時自動重新對焦 |

### 注意事項

| 限制 | 對策 |
|:---|:---|
| **紋理不足的區域** | 在 PCB 上設置對焦標靶區（fiducial mark 或印刷文字），先在該點對焦再移動檢測 |
| **光源一致性** | 對焦過程中光源必須穩定，否則亮度變化會影響 Laplacian 分數 |

## 總結

| 問題 | 結論 |
|:---|:---|
| **OpenCV vs YOLO？** | 不是二選一。YOLO 做主檢測引擎，OpenCV 做基礎設施（擷取、前處理、對位、對焦）。兩者缺一不可。 |
| **OpenCV 做 Z 軸對焦？** | 完全可行。Laplacian Variance + 爬山法是業界標準方案，Pi 5 效能綽綽有餘。 |
